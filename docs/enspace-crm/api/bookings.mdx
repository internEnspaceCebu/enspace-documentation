# Bookings

## Overview

The Bookings resource manages meeting room reservations in the Enspace CRM. A booking represents a scheduled use of a specific meeting room by a user or customer, including details like the booking date, time range, total amount, status, and payment status.

Bookings have a **many-to-many relationship** with Meeting Room Amenities through the `booking_meeting_room_amenity` pivot table. When creating or updating a booking, you can specify which amenities are needed.

This resource uses **optional authentication** — guests can create bookings and view them, but authorization is enforced via `BookingPolicy`: read responses are masked unless you own the booking, belong to the same customer, or are EA (Employee/Admin); update and delete require ownership or EA.

## Endpoints

| Method | URI | Auth Required | Description |
|--------|-----|:---:|-------------|
| `GET` | `/api/bookings` | Optional | List all bookings (paginated, 20/page) — sensitive fields masked unless owner/EA |
| `POST` | `/api/bookings` | Optional | Create a new booking (open to guests) |
| `GET` | `/api/bookings/{id}` | Optional | Retrieve a single booking — sensitive fields masked unless owner/EA |
| `PUT/PATCH` | `/api/bookings/{id}` | Optional | Update a booking (owner or EA only) |
| `DELETE` | `/api/bookings/{id}` | Optional | Delete a booking (owner or EA only) |
| `POST` | `/api/bookings/by-date-range` | Optional | Find bookings within a date range — sensitive fields masked unless owner/EA |

---

### GET /api/bookings

Returns a paginated list of all bookings (20 per page).

**Query Parameters:**

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `page` | integer | 1 | Page number |

**Response (200):** Paginated booking objects with standard Laravel pagination metadata. For non-owners (and non-EA), sensitive fields (`user_id`, `customer_id`, `booking_name`, `booking_email`, `booking_phone`, `total_amount`, statuses, audit columns, `custom_booking_price`, `booking_price`) are omitted; only `id`, `meeting_room_id`, `booking_date`, `start_time`, `end_time` are returned.

---

### POST /api/bookings

Creates a new booking with optional amenity associations.

**Request Body:**

| Field | Type | Required | Description |
|-------|------|:---:|-------------|
| `user_id` | integer | No | FK → `users.id`. Defaults to the authenticated user via the model. Only **OS Staff** may override it (403 otherwise) |
| `customer_id` | integer | No | FK → `customers.id`. Auto-populated from the user's company when `use_company_contract` is enabled; only **OS Staff** may set it explicitly (403 otherwise) |
| `use_company_contract` | boolean | No | When `true`, fills `customer_id` from the user's linked company (if not provided) |
| `meeting_room_id` | integer | Yes | FK → `meeting_rooms.id` |
| `booking_name` | string | Yes | Display name for the booking |
| `booking_email` | string | Yes | Contact email |
| `booking_phone` | string | Yes | Contact phone |
| `booking_date` | date | Yes | Date of the booking (`Y-m-d`) |
| `start_time` | time | Yes | Start time (`H:i`) |
| `end_time` | time | Yes | End time (`H:i`) |
| `total_amount` | numeric | Yes | Total cost (decimal) |
| `booking_status` | enum | No | `No-show`, `Pending`, `Ongoing`, `Completed` (default: `Pending`) |
| `payment_status` | enum | No | `No Payment`, `Down Payment`, `Full Payment` (default: `No Payment`) |
| `special_requests` | string | No | Any special requirements |
| `custom_booking_price` | integer | No | Custom negotiated price (nullable). When set, the computed `booking_price` accessor uses it instead of the room's `hourly_rate` |
| `meeting_room_amenities` | array | No | Array of amenity IDs to attach |

**Response (201):** Returns the created booking.

> **Note:** `created_by`, `updated_by`, `deleted_by` are **not** accepted in the request body — they are auto-populated from `auth()->id()` by the model.

---

### GET /api/bookings/{'{id}'}

Returns a single booking by ID.

**Response (200):** Booking object. Sensitive fields are masked unless the requester owns the booking, belongs to the same customer, or is EA.
**Error:** `404` if not found.

---

### PUT/PATCH /api/bookings/{'{id}'}

Updates a booking. All fields are optional. Amenities are **synced** (replaced) via `sync()`.

**Authorization:** The requester must own the booking (`user_id` matches) or be EA (`OSStaff`, `General Manager`, `Admin`, `Super Admin`). Otherwise `403`.

**Request Body:** Same as `POST`, all fields optional.

**Response (200):** Updated booking object.

---

### DELETE /api/bookings/{'{id}'}

Soft-deletes a booking. This is a **soft delete** — the record is marked with `deleted_at` but not removed from the database.

**Authorization:** The requester must own the booking (`user_id` matches) or be EA. Otherwise `403`.

**Response (204):** No content.

---

### POST /api/bookings/by-date-range

Finds all bookings within a specified date range, ordered by `booking_date` ascending.

**Request Body:**

| Field | Type | Required | Description |
|-------|------|:---:|-------------|
| `date_start` | date | Yes | Start of the date range |
| `date_end` | date | Yes | End of the range (`after_or_equal` `date_start`) |

**Response (200):** Collection of bookings within the range.

### Model: `Booking`

- **Traits:** `HasFactory`, `SoftDeletes`
- **Relationships:**
  - `user()` → `belongsTo(User::class)`
  - `customer()` → `belongsTo(Customer::class)`
  - `meetingRoom()` → `belongsTo(MeetingRoom::class)`
  - `meetingRoomAmenities()` → `belongsToMany(MeetingRoomAmenity::class)` with pivot `created_at`
- **Audit hooks:** `booted()` auto-sets `created_by`/`updated_by`/`deleted_by` from `auth()->id()`, defaults `user_id` to the authenticated user, and fills `customer_id` from the user's company.
- **Accessor:** `booking_price` → returns `custom_booking_price` if set, else the meeting room's `hourly_rate`.
- **Soft deletes:** Enabled

## Security

| Aspect | Status | Details |
|--------|:---:|---------|
| **Authentication Middleware** | Optional (`OptionalAuthenticate`) | If a bearer token is present, the user is resolved; otherwise proceeds unauthenticated |
| **Authorization Policy** | `BookingPolicy` | `create` → open; `update`/`delete` → booking owner (`user_id`) or EA; `viewFull` → owner, same `customer_id`, or EA |
| **Role-Based Access** | EA = `OSStaff`, `General Manager`, `Admin`, `Super Admin` | EA bypasses ownership checks via the policy `before()` hook |
| **Read masking** | `BookingResource` | Non-owners/guests only receive `id`, `meeting_room_id`, `booking_date`, `start_time`, `end_time`; all other fields hidden |
| **Field override** | OS Staff only | Only `OSStaff` may set/override `user_id` and `customer_id` (otherwise `403`) |

:::note
Creating a booking is intentionally open (guests can book a room). Update and delete require ownership or EA, enforced via `$this->authorize()` in the controller. Read is enforced at the resource layer, not by blocking the request.
:::

## Pending / Upcoming — Double-Booking Conflict Prevention

:::caution
The following is **not yet merged into `dev`**. It lives on the feature branch `feature/conflict-booking-check-for-bookings-table` (also bundled in `feature/payments`) and is documented here as an **upcoming** change — it does **not** describe current behavior and should not be relied upon in the API as it stands.
:::

Once merged, creating or updating a booking will prevent **overlapping time slots** for the same meeting room:

- **Schema:** new migration `2026_07_29_072253_add_index_in_bookings_table.php` adds a composite index `bookings_room_date_index` on `(meeting_room_id, booking_date)` to speed up conflict lookups.
- **Time validation:** `end_time` must be after `start_time` on both `store()` and `update()` — otherwise a `422` is returned.
- **Conflict detection:** a new `preventBookingConflict()` runs inside a `DB::transaction`, locks matching rows with `lockForUpdate()`, then checks for overlaps via `Booking::bookingConflictCheck()`.
- **Conflict response:** on overlap, a `422` is returned with:
  ```json
  {
    "message": "The given data was invalid.",
    "errors": { "booking_date": ["This time slot is already booked."] }
  }
  ```
- **Midnight-span support:** `Booking::toDateTimeRange()` treats an `end_time` that is not after `start_time` as ending on the **following day** (booking spans midnight).
- **Factory:** `BookingFactory` now generates valid windows (start between `08:00` and `18:00`, duration `1–4` hours).
