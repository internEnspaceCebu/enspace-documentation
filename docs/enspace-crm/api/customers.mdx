# Customers

## Overview

The Customers resource manages company/tenant information in the Enspace CRM. Each customer represents a business entity with company details (name, email, phone, TIN number), up to two contact persons, and an optional description.

Customers are a **core entity** in the system — they are referenced by Users, Bookings, Contracts, and Inquiries. The Customer resource is **fully authenticated** (`auth:sanctum`) and **policy-protected**, making it one of the most securely controlled resources in the API.

## Endpoints

| Method | URI | Auth Required | Description |
|--------|-----|:---:|-------------|
| `GET` | `/api/customers` | Yes (`auth:sanctum`) | List all customers (paginated, 20/page, max 100) |
| `POST` | `/api/customers` | Yes (`auth:sanctum`) | Create a new customer |
| `GET` | `/api/customers/{id}` | Yes (`auth:sanctum`) | Retrieve a single customer |
| `PUT/PATCH` | `/api/customers/{id}` | Yes (`auth:sanctum`) | Update a customer |
| `DELETE` | `/api/customers/{id}` | Yes (`auth:sanctum`) | Soft-delete a customer |
| `GET` | `/api/customer` | Yes (`auth:sanctum`) | Custom pagination endpoint (same as index, accepts `per_page`) |

---

### GET /api/customers

Returns a paginated list of all customers. Requires `viewAny` policy authorization.

**Query Parameters:**

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `page` | integer | 1 | Page number |
| `per_page` | integer | 20 | Items per page (max: 100, min: 1) |

**Response (200):** Paginated customer objects.

---

### POST /api/customers

Creates a new customer. Requires `create` policy authorization.

**Request Body:**

| Field | Type | Required | Description |
|-------|------|:---:|-------------|
| `company_tenant_name` | string | Yes | Company or tenant name |
| `company_email` | string | Yes | Company email (must be unique) |
| `company_phone` | string | Yes | Philippine phone format |
| `tin_number` | string | No | Tax Identification Number |
| `is_expanded_withholding_tax` | boolean | No | Default: `false` |
| `contact_person_01` | string | Yes | Primary contact person's name |
| `contact_person_01_phone` | string | Yes | Primary contact's phone |
| `contact_person_01_email` | string | Yes | Primary contact's email |
| `contact_person_01_address` | string | Yes | Primary contact's address |
| `contact_person_02` | string | No | Secondary contact person's name |
| `contact_person_02_phone` | string | No | Secondary contact's phone |
| `contact_person_02_email` | string | No | Secondary contact's email |
| `contact_person_02_address` | string | No | Secondary contact's address |
| `description` | string | No | Additional notes |

**Response (201):** Returns the created customer.

---

### GET /api/customers/{'{id}'}

Returns a single customer by ID. Requires `view` policy authorization.

**Response (200):** Customer object.
**Error:** `403` if not authorized, `404` if not found.

---

### PUT/PATCH /api/customers/{'{id}'}

Updates a customer. Requires `update` policy authorization. All fields are optional.

**Request Body:** Same as `POST`, all fields optional.

**Response (200):** Updated customer object.

---

### DELETE /api/customers/{'{id}'}

Soft-deletes a customer. Requires `delete` policy authorization. Uses Eloquent's `SoftDeletes` — the record is marked with `deleted_at` and `deleted_by` but not removed from the database.

**Response (204):** No content.

---

### GET /api/customer

Custom pagination endpoint that behaves identically to `GET /api/customers`. Requires `viewAny` policy authorization.

**Query Parameters:**

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `page` | integer | 1 | Page number |
| `per_page` | integer | 20 | Items per page (max: 100, min: 1) |

**Response (200):** Paginated customer objects.

| `contracts` | Indirect (FK) | `contracts.customer_id` → `customers.id` (`ON DELETE SET NULL`) |

```
customers (1) <──── (N) users        [SET NULL on delete]

customers (1) <──── (N) inquiry      [SET NULL on delete]
```

### Model: `Customer`

- **Traits:** `HasFactory`, `SoftDeletes`
- **Relationships:** `users()` (`hasMany`) and `contracts()` (`hasMany`)
- **Soft deletes:** Enabled. Uses `booted()` lifecycle hooks for automatic tracking.
- **Lifecycle hooks:**
  - `creating` → Sets `created_by = auth()->id()`
  - `updating` → Sets `updated_by = auth()->id()`
  - `deleting` → Sets `deleted_by = auth()->id()` (only on soft delete, not force delete)

## Security

| Aspect | Status | Details |
|--------|:---:|---------|
| **Authentication Middleware** | `auth:sanctum` | Requires a valid Sanctum bearer token |
| **Authorization Policies** | Yes (`CustomerPolicy`) | Full policy on all CRUD operations |
| **Role-Based Access** | Yes | See detailed breakdown below |

### CustomerPolicy Breakdown

The `CustomerPolicy` defines a `hasFullAccess()` helper that returns `true` for roles: `OS Staff`, `General Manager`, `Admin`, `Super Admin`.

| Operation | Policy Method | Who Can Access |
|-----------|:---:|----------------|
| List all | `viewAny` | `OS Staff`, `General Manager`, `Admin`, `Super Admin` |
| Create | `create` | `OS Staff`, `General Manager`, `Admin`, `Super Admin` |
| View one | `view` | `OS Staff`, `General Manager`, `Admin`, `Super Admin` **OR** `Member` viewing their own linked customer (`$user->customer_id === $customer->id`) |
| Update | `update` | `OS Staff`, `General Manager`, `Admin`, `Super Admin` |
| Delete | `delete` | `OS Staff`, `General Manager`, `Admin`, `Super Admin` |

:::note
`Guest` users have **no access** to any customer operations, not even viewing their own linked customer record.
:::

### User Role Hierarchy

| Role | Can Access Customers? |
|------|:---:|
| `guest` | No |
| `member` | Own record only (view) |
| `OS Staff` | Full access |
| `General Manager` | Full access |
| `Admin` | Full access |
| `Super Admin` | Full access |

## Audit Tracking

| Field | Column Exists | Auto-Populated | FK to Users | Notes |
|-------|:---:|:---:|:---:|-------|
| `created_by` | Yes | **Yes** | Yes (`ON DELETE SET NULL`) | Set in `Customer::booted()` via `auth()->id()` |
| `updated_by` | Yes | **Yes** | Yes (`ON DELETE SET NULL`) | Set in `Customer::booted()` via `auth()->id()` |
| `deleted_by` | Yes | **Yes** | Yes (`ON DELETE SET NULL`) | Set in `Customer::booted()` via `auth()->id()` |

:::tip
The `Customer` model is the **only resource** in the system with fully implemented audit tracking. The tracking columns are also the only ones that are proper **foreign keys** to the `users` table (via migration `2026_07_09_054636`).
:::
